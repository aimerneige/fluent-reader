This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Run

```bash
npm install          # Install dependencies
npm run build        # Compile TypeScript via webpack (outputs to dist/)
npm run electron     # Run the Electron app
npm start            # Build + run in one step
npm run format       # Format code with Prettier
```

There is no test framework configured. Verification is done by running the app. Note: `npx tsc --noEmit` will show pre-existing type errors in node_modules and some source files — these are expected and do not block the build.

Packaging: `npm run package-win`, `npm run package-mac`, `npm run package-linux`.

## Architecture

Fluent Reader is a desktop RSS reader built with **Electron + React + TypeScript + Redux + Fluent UI**.

### Three Webpack Entry Points

The webpack config (`webpack.config.js`) compiles three separate bundles:

1. **Main process** (`src/electron.ts` → `dist/electron.js`) — target: `electron-main`. Window management, IPC handlers, system integration.
2. **Preload script** (`src/preload.ts` → `dist/preload.js`) — target: `electron-preload`. Exposes two bridges to the renderer via `contextBridge`:
   - `window.settings` — from `src/bridges/settings.ts` (font, theme, proxy, etc.)
   - `window.utils` — from `src/bridges/utils.ts` (IPC wrappers, clipboard, dialogs, webview listeners)
3. **Renderer** (`src/index.tsx` → `dist/index.js`) — target: `web`. The React application.

### IPC Communication

Renderer ↔ Main communication goes through the preload bridges (`src/bridges/`). The renderer calls `window.settings.*` and `window.utils.*` which use `ipcRenderer.invoke()` / `ipcRenderer.sendSync()` internally. Never import `electron` directly in renderer code.

### State Management (Redux)

Redux store is created in `src/scripts/reducer.ts` with these slices (each in `src/scripts/models/`):

| Slice | File | Purpose |
|-------|------|---------|
| `app` | `app.ts` | App-level state (locale, theme, menus, fetch status) |
| `sources` | `source.ts` | RSS feed source definitions |
| `items` | `item.ts` | Article items (NeDB/Lovefield storage) |
| `feeds` | `feed.ts` | Feed display state (filter, search, loaded items) |
| `groups` | `group.ts` | Source grouping/folders |
| `page` | `page.ts` | Navigation/page state |
| `service` | `service.ts` | Sync service configuration (Fever, Feedbin, etc.) |

Async actions use Redux Thunk. Selectors use Reselect (`src/scripts/models/feed.ts`).

### Component Organization

- **`src/components/`** — React presentational components (class components, some functional)
- **`src/containers/`** — Redux-connected container components using `connect()` (maps state/dispatch to props)
- **`src/components/settings/`** — Settings panel subcomponents
- **`src/components/cards/`** — Article card variants (card, list, magazine, compact views)
- **`src/components/feeds/`** — Feed list display components

### Article Rendering

Articles are rendered inside an Electron `<webview>` tag (`src/components/article.tsx`). The webview loads either:
- A local HTML template (`dist/article/article.html`) with article content passed via URL params
- The original webpage URL directly

Webview keyboard/context events are forwarded to the main renderer through `window.utils.addWebviewKeydownListener()` / `addWebviewContextListener()`.

### Static Assets in `dist/`

CSS files in `dist/styles/` and article viewer files in `dist/article/` are **static assets, not generated by the build**. They are hand-maintained and directly referenced at runtime. Edit them in place.

### Internationalization

Uses `react-intl-universal`. Locale JSON files are in `src/scripts/i18n/`. English (`en-US.json`) is the fallback. Keys are namespaced (e.g., `article.markRead`, `context.copyURL`). When adding new UI strings, always add to both `en-US.json` and `zh-CN.json` at minimum.

## Code Style

- Prettier config: 4-space tabs, no semicolons, JSX bracket on same line, arrow parens avoided when possible
- Fluent UI (`@fluentui/react` v8) for all UI components — use `CommandBarButton`, `IconButton`, `Stack`, `FocusZone`, etc.
- Class components are used throughout (not hooks), with arrow function methods for auto-binding
- Platform-aware shortcuts: use `window.utils.platform === "darwin"` to distinguish macOS (Cmd) from Windows/Linux (Ctrl). See `platformCtrl()` in `src/scripts/utils.ts`.
